# Day10：Python 工程化入门（代码规范、命名规范、模块化拆分）

## 【核心知识点】

### 1. PEP8 代码基础规范

- 缩进规则：统一使用 4 个空格，禁止使用制表符 Tab
- 行长度：单行代码不超过 120 字符，过长则合理换行拆分
- 空行规则：函数之间、类之间空两行；类内方法之间空一行；逻辑块之间空一行
- 注释规范：行内注释与代码间隔至少两个空格；函数 / 类使用三引号文档字符串说明功能
- 格式细节：运算符两侧、逗号后加空格，提升代码可读性

### 2. 统一命名规范

| 标识符类型    | 命名规则               | 正确示例                           |
|----------|--------------------|--------------------------------|
| 变量 / 函数  | 蛇形命名法，全小写，单词间下划线分隔 | `user_name`、`calculate_total`  |
| 类名       | 大驼峰命名法。每个单词首字母大写   | `StudentInfo`、`FileHandler`    |
| 全局常量     | 全大写，单词间下划线分隔       | `MAX_SIZE`、`DEFAULT_PORT`      |
| 模块 / 文件名 | 蛇形命名法，全小写          | `user_utils.py`、`data_process` |

### 3. 模块化拆分原则

- 单一职责：每个模块、每个函数只负责一项功能，避免大而全的单文件堆积
- 导入分层：按「标准库 → 第三方库 → 本地模块」顺序排列，层间空一行
- 复用抽离：通用工具函数单独封装为公共模块，减少重复代码
- 规避循环导入，模块之间避免双向引用，防止出现导入报错

## 【今日易错点】

1. 导入语句不按分层规范排列，混合标准库与第三方库，不符合 PEP8 规范
2. 命名风格混用，变量用大驼峰，类用蛇形命名，降低代码可读性
3. 单文件堆积全部业务逻辑不拆分，后续迭代与维护成本极高
4. 漏写 `if __name__ == "__main__"` 主入口判断，模块被导入时会直接执行业务代码
5. 单个函数承载多项功能，职责不清晰，可复用性与可测试性差

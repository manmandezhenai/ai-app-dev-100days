# Day16：Git 分支管理（创建、切换、合并、冲突处理）

## 【核心知识点】

### 1. 分支基础操作

- 查看本地分支：`git branch`，当前分支前带 `*` 标记
- 创建新分支：`git branch 分支名`，创建后仍停留在当前分支
- 切换分支：`git checkout 分支名` 或 `git switch 分支名`，切换到指定分支
- 创建并切换分支：`git checkout -b 分支名`，一步完成创建与切换
- 查看全部分支：`git branch -a`，同时展示本地与远程分支

### 2. 分支合并操作

- 合并前提：先切换到接收合并的目标分支，通常为主分支
- 执行合并：`git merge 待合并分支名`，将指定分支内容合并到当前分支
- 无冲突场景：自动完成合并提交，生成新的合并版本记录
- 有冲突场景：暂停合并流程，标记冲突文件，等待手动处理后完成提交
- 合并完成后，待合并的源分支仍保留，不会自动删除

### 3. 合并冲突处理步骤

1. 执行 merge 出现冲突提示后，运行 `git status` 查看所有冲突文件
2. 打开冲突文件，定位 `<<<<<<<`、`=======`、`>>>>>>>` 包裹的冲突区域
3. 手动编辑保留最终正确内容，完整删除所有冲突标记符号
4. 修改完成后，执行 `git add 冲突文件` 标记该文件冲突已解决
5. 全部冲突解决后，执行 `git commit` 完成合并提交

### 4. 分支删除与清理

- 删除已合并的本地分支：`git branch -d 分支名`
- 强制删除未合并的本地分支：`git branch -D 分支名`，未合并内容会丢失
- 分支命名规范：统一使用蛇形命名，按功能 / 修复 / 优化前缀命名，见名知意

## 【今日易错点】

1. 切换分支前未提交当前工作区修改，变更内容会被带到新分支，造成代码混乱
2. 合并前未切换到目标主分支，会将主分支内容反向合并到开发分支
3. 处理冲突时遗漏删除冲突标记符号，直接提交会导致代码语法报错
4. 使用 `-d` 删除未合并的分支会报错，确认丢弃分支请使用 `-D` 强制删除
5. 功能合并完成后不及时清理废弃分支，长期积累会导致分支列表杂乱

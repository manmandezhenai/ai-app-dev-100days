# Day17：远程仓库操作与协作提交规范

## 【核心知识点】

### 1. 远程仓库关联管理

- 关联远程仓库：`git remote add origin 远程仓库地址`，origin 为默认远程仓库别名
- 查看远程仓库地址：`git remote -v`，显示所有关联的远程仓库与对应地址
- 修改远程仓库地址：`git remote set-url origin 新地址`，更新已关联的远程地址
- 移除远程仓库关联：`git remote remove origin`，解除本地与远程仓库的绑定

### 2. 代码推送与拉取同步

- 推送本地分支到远程：`git push origin 本地分支名`，将本地提交同步到远程对应分支
- 首次推送关联分支：`git push -u origin 分支名`，建立本地与远程分支的追踪关系
- 拉取远程最新代码：`git pull origin 分支名`，拉取并自动合并远程分支到当前本地分支
- 仅拉取不合并：`git fetch origin`，获取远程更新但不自动合并，需手动执行 merge

### 3. 远程仓库克隆

- 克隆完成仓库：`git clone 远程仓库地址`，下载完整远程仓库到本地，自动关联 origin
- 克隆指定分支：`git clone -b 分支名 远程分支仓库地址`，仅拉取指定分支内容
- 克隆后默认进入主分支，本地仅包含主分支，其他远程分支需手动切换拉取

### 4. 约定式提交规范

- 统一提交格式：`类型(作用范围)：提交描述`，描述简洁清洗，不超过 50 字符
- 常用提交类型：

| 类型         | 用途说明               |
|------------|--------------------|
| `feat`     | 新增功能、新特性开发         |
| `fix`      | 修复代码 bug           |
| `docs`     | 文档、注释、README 更新    |
| `style`    | 代码格式调整，不影响业务逻辑     |
| `refactor` | 代码重构，无功能新增与 bug 修复 |
| `chore`    | 构建工具，依赖配置等工程化变更    |

## 【今日易错点】

1. 推送代码前未拉取远程最新版本，会导致推送冲突，推送前先执行 pull 同步代码
2. 首次推送漏加 `-u` 参数，后续推拉代码需每次手动指定分支名
3. 直接在主分支开发提交，协作场景下易污染主分支，应创建功能分支开发
4. 提交信息类型与内容不匹配，会导致版本日志混乱，无法快速定位变更用途
5. 遇到推送冲突直接强制推送，会覆盖他人提交代码，需先拉取解决冲突后再推送

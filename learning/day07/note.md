# Day07：异常处理与代码调试基础

## 【核心知识点】

### 1. 基础异常捕获语法

```python
try:
    可能触发异常的执行代码
except 异常类型:
    捕获到对应异常后的处理逻辑
```

- `try` 代码块包裹可能出错的业务代码
- 代码执行无异常时跳过 `except` 块，出错则进入对应异常处理逻辑
- 捕获异常后程序继续向下运行，不会直接终止退出

### 2. 常见内置异常类型

| 异常类型                | 触发场景                    |
|---------------------|-------------------------|
| `ValueError`        | 传入值类型正确但内容不合法，如字符串转整数失败 |
| `TypeError`         | 数据类型不匹配，如字符串与数字直接相加     |
| `IndexError`        | 列表 / 字符串索引超出有效范围        |
| `KeyError`          | 访问字典不存在的键               |
| `ZeroDivisionError` | 除法运算中除数为 0              |
| `FileNotFoundError` | 读取不存在的文件路径              |

### 3. 多异常捕获与分支扩展

```python
try:
    业务执行代码
except 异常类型1:
    异常1处理逻辑
except 异常类型2:
    异常2处理逻辑
else:
    无异常时执行的逻辑
finally:
    无论是否异常都会执行的收尾逻辑
```

- 多个 `except` 按顺序匹配异常，命中第一个后不再向下匹配
- `else` 块仅在无如何异常时执行
- `finally` 块始终执行，常用于资源释放、连接关闭等场景

### 4. 代码基础调试方法

- `print` 调试法：在关键逻辑节点打印变量值，跟踪数据变化
- 注释定位法：逐步注释代码段，缩小报错范围定位问题行
- 异常信息读取：优先关注报错行号、异常类型与错误描述
- 分段验证：拆分长代码为小段，逐段运行验证正确性

## 【今日易错点】

1. 空 `except`会捕获所有异常，容易掩盖真实错误，工程中必须指定具体异常类型
2. 父类异常写在子类异常前，会导致子类异常永远无法被匹配捕获
3. `finally` 中编写 `return` 语句，会覆盖 `try` 和 `except` 内的返回结果
4. 异常捕获范围过大，会隐藏正常逻辑 bug，增加排查难度
5. 只打印自定义提示不输出异常信息，不利于快速定位问题根源

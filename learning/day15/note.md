# Day15：Git 基础命令（初始化、提交、暂存区、日志、回退）

## 【核心知识点】

### 1. 仓库初始化与状态检查

- 初始化仓库：在项目根目录执行 `git init`，生成本地 Git 仓库
- 查看查看状态：执行 `git status`，查看工作区、暂存区文件变更状态
- 工作区域划分：工作区（本地编辑的文件）、暂存区（临时存放待提交文件）、本地仓库（永久保存的版本记录）

### 2.暂存区操作

- 添加单个文件到暂存区：`git add 文件名`
- 批量添加所有变更文件：`git add .`
- 取消文件暂存状态：`git rm --cached 文件名`，文件保留在工作区，不删本地文件
- 暂存区作用：分批整理提交内容，避免一次性提交无关变更

### 3. 本地提交操作

- 提交暂存区内容到本地仓库：`git commit -m "提交描述信息"`
- 提交信息需求：简洁清晰描述本次变更内容，禁止空描述
- 补充修改最近一次提交：`git commit --amend`，可修改提交信息或补充遗漏文件

### 4. 提交日志查看

- 查看完整提交日志：`git log`，显示提交哈希、作者、时间、提交描述
- 查看简洁版日志：`git log --oneline`，每行显示一条提交记录，便于快速浏览
- 查看最近 N 记录：`git log -n 数量`，指定显示的提交条数

### 5. 版本回退操作

- 硬重置回退：`git reset --hard 版本号`，工作区、暂存区、仓库同步回退到指定版本
- 操作记录查询：`git reflog`，查看所有历史操作记录，可找回已回退的版本号
- 执行前提：硬重置前确认未提交的重要代码已备份，避免内容丢失

## 【今日易错点】

1. 未执行 `git add` 将文件加入暂存区直接提交，变更内容不会进入版本记录
2. 在非项目根目录执行 `git init`，会造成仓库层级错乱，需先切换到目录根目录
3. `git reset --hard` 会直接丢弃未提交的工作区修改，执行前务必确认重要内容已备份
4. 提交信息描述模糊随意，后续排查版本变更时无法快速定位修改内容
5. 误删文件后未通过 Git 恢复直接重建，会丢失文件历史版本记录
